# 视频原片治理与外置归档（MEDIA_ARCHIVE_OPS）

> 对象：`library/01_video/`（原片，13G，gitignore 不入库）与其转写孪生目录 `library/04_transcript/`。
> 原则：**本地是唯一权威源；外置 U 盘/硬盘只是只读字节副本；原片不降质、不重编码**。决策依据见 [DECISIONS.md](./DECISIONS.md) ADR-013，网盘备份另见 [NETDISK_SYNC.md](./NETDISK_SYNC.md)。

## 1. 编码策略：已下载片源不转码、原样归档

老许片源是 B 站**已高度压缩的低码率流**（2026-09-14 全 743 部普查）：编码 HEVC 309 / H.264 336 / AV1 98；码率中位 657 kbps、均 767 kbps、区间 298–2077 kbps；总时长约 41h、13.36 GiB、单条均约 18MB。

三样本 × 多档实测（hi-H.264 2076k、mid-HEVC 537k、AV1 857k，保持原分辨率）：

| 做法 | 体积 | 画质 SSIM | 结论 |
|---|---|---|---|
| x265 CRF24–26（保质量档） | **×1.05–1.72 反而变大** | 0.927–0.985 | 源码率已低于该工作点，保画质必须更高码率 |
| x265 CRF28–32（才开始变小） | ×0.56–0.86 | **0.91–0.97** | 珠宝颜色渐变/火彩/净度/烧入字幕变软出带 |
| x264 CRF20（兼容档） | ×1.86–3.11 | — | 更占空间 |

肉眼透明需 SSIM ≥ 0.98；要在这种源上"既保珠宝观感与字幕清晰又缩小"不存在可行工作点，且外置盘空间充足（13G 占用极低）。**故统一原字节留存/归档，不重编码。** 唯一可能需要转码的理由是老设备不解 AV1（98 部）的播放兼容性——当前无此需求，将来需要时只对 AV1 子集、单独导出兼容副本，**不替换原片**。

> 该实测以更准数据取代 README 中 2026-09-11"重压省 26–35%"的早期估算。

## 2. 漏合流 / 纯音频文件排查与无损修复

B 站 DASH 是视频流、音频流分开下载再合流；若流水线在合流前被中断，会留下 `xxx.f30074.mp4`（纯画面）+ `xxx.f30280.m4a`（纯声音）两个分流，表现为目录里出现 `.m4a` 或带 `.f数字.` 后缀的文件。

```bash
# 1) 全库找未合流分流（正常应为 0）
find library/01_video -type f \( -name '*.f[0-9]*.mp4' -o -name '*.m4a' \)

# 2) 分别确认：一个有 video 无 audio，一个只有 audio，时长应几乎相等
ffprobe -v error -show_entries stream=codec_type:format=duration -of default=nw=1 "纯画面.f30074.mp4"
ffprobe -v error -show_entries stream=codec_type:format=duration -of default=nw=1 "纯声音.f30280.m4a"

# 3) 无损封装合流（-c copy 不重编码；输出大小≈两流之和）
ffmpeg -i "纯画面.f30074.mp4" -i "纯声音.f30280.m4a" \
  -map 0:v:0 -map 1:a:0 -c copy -movflags +faststart "成品 [BVxxx].mp4"

# 4) 校验成品同时含 video+audio、时长正确后，才删两个分流
ffprobe -v error -show_entries stream=codec_type -of csv=p=0 "成品 [BVxxx].mp4"
```

合流不依赖音频转写（转写本就基于音频流，通常已完整）；修复后知识条目与网盘文本层无需重做。

## 3. 规范命名：类内序号 + 标题 + BV

- 规则：`library/01_video/<分类>/<NNN>_<标题> [<BV号>].mp4`；`04_transcript/<分类>/` 下转写目录取**同名 stem**（无扩展名）一一对应。
- **序号方案 A（类内编号）**：每个分类目录内按 `created`（unix 秒，同秒按 BV 稳定排序）从 `001` 起升序。不同分类各自从 001 开始属正常（路径不同不冲突）；**全局唯一性由末尾 `[BV号]` 承担**，它同时是关联转写/知识条目的键。相较"全库 001–743 全局编号"，类内编号在每个目录内是连续时间线，且将来某分类新增视频只续本类编号、不扰动其它类。
- 标题清洗（只清洗文件名，不改 manifest 标题）：去 emoji 与变体选择器/零宽字符；去 ASCII 非法 `\ / : * ? " < > |` 与全角斜杠；折叠空白；去掉标题自带 `[BV]` 后统一补；UTF-8 超 228 字节截断加省略号，给 FAT32/网盘留余量。
- **台账无需改**：`manifest.json` 的 `video` 字段只到**分类目录**、不含文件名（全库 grep 不到 `.mp4`），故重命名不影响台账。
- **两阶段安全改名（防链式覆盖）**：先把所有旧名改成同目录唯一临时名（如 `.rn1_<i>.mp4`），再统一改成最终名；批量前先出 dry-run 计划，要求 0 孤儿 / 0 缺失 / 0 碰撞 / 0 超长 / 0 重名才执行。旧→新映射留 `workspace/`（过程件、不入库）作回滚依据。

## 4. 外置介质（U 盘/移动硬盘）rsync 归档

- 归档根目录用**博主中文名**：`<挂载点>/宝石学家老许/01_视频原片/<22 分类>/…`，预留 `02_…` 给将来图文/转写。介质内其它内容（如系统启动盘）不动。
- **FAT32/exFAT 用 `-rt`，不要用 `-a`**（避免 `-p/-o/-g` 在不支持权限的文件系统刷警告），并加 `--modify-window=2` 容忍 FAT 的 2 秒时间精度：

```bash
rsync -rtv --modify-window=2 --partial --timeout=180 \
  --exclude='.DS_Store' --exclude='._*' \
  "library/01_video/" "/Volumes/<盘>/宝石学家老许/01_视频原片/"
```

- 幂等可续：中断后原样重跑，已传且大小一致的自动跳过，`--partial` 保留半截续传；若目标残留**旧名**半成品，先用第 3 节的旧→新映射在目标盘同盘改名对齐，再 rsync 补齐，避免新旧名混杂。
- FAT32 单文件上限 4GB：本库最大单条约 98MiB，安全；若将来出现 >4GB 源，介质需换 exFAT。
- rsync 日志里非 ASCII 文件名显示成 `#数字` 转义是正常输出（非乱码），实际文件名以 `ls` 为准。

## 5. 归档后三重校验（全过才算完成）

1. **数量与分类**：22 个分类逐一比对本地与目标的 mp4 数（本库 743=743），类内序号 001..N 连续、无分流/m4a/临时名残留。
2. **总逻辑字节**：用 `stat` 求和（不要用 `du`，FAT 簇对齐会让块占用偏大）：
   ```bash
   find library/01_video -type f -name '*.mp4' -exec stat -f%z {} + | awk '{s+=$1}END{print s}'
   ```
   本地与目标应**差 0**（本库 14,343,313,627 B）。
3. **内容校验和 + 抽播**：`rsync -rcni --modify-window=2 <src>/ <dst>/` 逐字节比对，**文件行应为 0**（无内容差异）；再从目标盘路径直接 `ffprobe` 抽验含合流条、AV1、合集首尾在内的若干文件，均须 video+audio 双流。

> **FAT32 时间戳现象（不是错误）**：FAT 只能存偶数秒 mtime，与本地精确秒天然差 0–2 秒，普通 `rsync -rtni` 可能长期列出 `.f..t....`（仅 t/T 时间位、无 s 大小位、无 c 校验位、方向位为 `.` 表示不传内容）。判定内容是否一致以第 5.3 的 `-c` 校验和为准；该 t 位在 FAT32 上无法刷平，换 exFAT（10ms 精度）可消除，无需为此重做归档。

## 6. 边界

- 归档/备份**不删本地原片**（本地唯一权威源）；不借归档之名做降质转码。
- 原片、音频、转写、`workspace/` 过程件一律不入公有 Git（见 `.gitignore`、ADR-012）；本 SOP 与 ADR 是入库的"方法"，不是"原料"。
