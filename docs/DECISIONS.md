# 决策记录（ADR，轻量）

> 每个重要决策记一条：背景→决定→理由→代价/复盘点。新决策追加在最上面，编号递增、不删旧条（被推翻就标 Superseded）。

## ADR-012 来源平台无关化 + 新增 ReportNote；仓库转公有，原料/逐字稿一律不入库
- **背景**：知识库后续要纳入更多来源（其他 UP、公众号/视频号/抖音、电子书、第三方报告 PDF、付费社区等），不能绑死"老许 + B 站"；同时用户 2026-09-14 要求仓库由私有转**公有**。首个外部来源是生财有术社区珠宝创业情报（548→174 篇综合）。
- **决定**：
  1. **来源层平台无关化**：新增通用原始层 `library/08_sources/<source_id>/{raw,cleaned,SOURCE.md,manifest.json}`，`source_id=<平台>-<主体>`、平台用开放枚举（bili/douyin/wxchannel/wxmp/xhs/podcast/book/report/community/web），加平台只加目录、不改架构；老许既有 01/04/06/07 路径不动。
  2. **知识 type 表"载体形态"、与作者/平台解耦**：外部视频→VideoNote、图文/公众号→ArticleNote、电子书→BookNote；**新增 `ReportNote`** 承接第三方 PDF 报告/综合研究的清洗结果，落 `concepts/reports/`。融合仍只发生在 topics（多来源分栏）。
  3. **流水线分层（三层，不混淆）**：①原始下载件（视频/PDF/原网页）与②逐字转写/原文抽取（transcript、article/ocr、采集 CSV）都是**原料**，放 08_sources 的 raw/cleaned（或既有 01/04/06），**一律 gitignore、只留本地、不进公有仓**；只有③"用自己话重组、带来源"的知识成品（stable 条目、topics、reports、docs、代码、台账元数据）入库。
  4. **仓库转公有（变更 ADR-003 的"默认私有"）**：清掉含逐字稿的全部 Git 历史、以干净历史重建并设 public；既有 743 VideoNote 中仅 20 篇 stable 入公有仓，733 篇逐字 draft 取消跟踪、留本地，精修一篇（转"自己话成品"）放行一篇；04_transcript、06_articles 整体不入库。版权合规细节用户后续另行评估，本决策先确立"原料不入库、只公开成品"的结构。
- **理由**：来源泛化避免每接一个平台就改一次架构；载体分型与作者解耦后 Video/Article/Book/Report 可复用同一套 OKF 规则；公开成品、隔离原料，使公有仓不包含他人逐字内容，同时保留本地完整生产资料（本地仍是唯一权威源）。
- **代价/复盘**：公有仓当前成品较少（20 stable + topics + 外部 ReportNote + 文档），733 draft 需随 M1 精修逐步放行；`.gitignore` 对 videos 采用"默认忽略 draft、逐行放行 stable/index"的成品门禁，stable 增删需同步该段；旧私有仓 `byte886/gemology-kb` 已删除、同名不再沿用，公有仓为 `byte886/jewelry-knowledge`（单条干净历史，2026-09-14 核对：104 文件、无原料/凭证）。

## ADR-011 图文采集走「登录态 detail + Vision OCR + 去水印 + 内容类型分类」，现货/设计稿同为知识
- **背景**：M2 图文动态 DRAW 共 4366 篇，实测动态本身几乎零文字，内容烧在图里（1080 宽竖卡），且每张铺满固定斜排水印；需确定取数/OCR/清洗/分类路线。用户 2026-09-13 明确：**现货价格、货盘、克拉与品级、售出状态、设计稿本身就是珠宝知识的一部分**，不做"纯科普"过滤。
- **决定**：
  1. 取数：登录小号 Chrome（.chrome-prof3/9223）页面上下文 `fetch` detail（`draw.items` 与 `opus.pics` 双通道），单线程慢速（detail 3–5s、图 0.8–1.8s），不走游客列表接口；
  2. OCR：用 macOS 原生 Vision（离线免费、zh-Hans+en-US、accurate），不引入 Paddle 等重依赖（承 ADR-007）；
  3. 清洗与纠错：`clean_watermark.py` 整行判定去固定品牌水印，再经 `correct_ocr.py` 做零误伤高置信纠错（ct 单位/小数点/特异形近）；原始 OCR 保留在 `ocr/` 可追溯，`article.md` 用清洗纠错后文本，frontmatter 同时记 `ocr_chars`/`clean_chars`；每批用 `verify_articles.py` 做"图数=OCR数=清单数"完整性对账（思路移植高顿 verify_ocr）；
  4. 分类：启发式 `content_type`（goods_price 现货行情 / catalog 款式目录 / event 直播活动 / knowledge 知识科普 / mixed_text / image_only 纯图设计稿），**只分类、不丢弃**；纯图/设计稿保留原图并标 image_only；
  5. 分层：原始层 `library/06_articles/raw/<yyyy-mm>/<id>/`（images+ocr+article+meta），文本入库、图片二进制 gitignore；知识层 ArticleNote 编译留到 M2-2。
- **理由**：20 篇试点 81 图全部采通，链路稳定；Vision 对中文货品标签（皇家蓝/无烧矢车菊/18k金祖母绿耳钉）识别准，去水印后纯设计稿从数百字水印归零、现货货盘完整保留；分类让"卖货/展示"内容可直接服务做号选品、货盘与价格带分析，契合"做号弹药库"终局（ADR-006）。
- **代价/复盘**：Vision 对小字段落存在 `ct→c/g`、小数点→逗号、形近字（蓝→遊、椭圆→椭园）等可控错误，已由 correct_ocr 收敛高置信部分；但手机货盘长图字段密集、碎错多变（如"3的/色孙/祖母姿"无法高置信还原），正则只把可读性拉到基线，**字段级结构化（品类×克拉×切工×价格带）留 M2-2 对 goods_price 图走多模态视觉重识别**（对齐高顿 OCR SOP"表格交 AI 视觉"）；20 篇试点 knowledge 类为 0（图文以现货/设计稿/活动为主，知识主要在视频），全量后复核该占比；全量 4366 篇约 1.4 万图，按当前节奏约 10 小时量级，需 nohup 后台分批断点续跑。

## ADR-010 网盘不建珠宝独立 App，共用沙箱 + 领域目录隔离
- **背景**：曾考虑为珠宝单独申请百度网盘开放平台应用以获得独立沙箱 `/apps/<应用名>/`；个人认证可建应用数网上说法矛盾（1 个 / 2 个）。
- **决定**：不另建应用；珠宝成品同步到现有「CPA课程归档」沙箱下的平级目录 `珠宝知识库/`，与 `会计知识库/`（含高顿）、`股票知识库/` 按领域隔离。
- **理由**：同一账号、同一 token 下，沙箱内"领域知识库"目录级隔离与独立 App 沙箱在功能/权限/备份上等价；云端已按领域分好，同步映射与断点已实测可用；省去再走 OAuth、再维护一套凭证和切换 `NETDISK_BASE` 的成本。
- **复盘点**：将来若换账号或需对外授权再独立，流程见 `docs/NETDISK_SYNC.md` 第 8 节。

## ADR-009 防风控：直连/慢速/隔离 profile/低频
- **决定**：B 站全程直连、单线程限速随机间隔、撞 412/-352 立即冷却不重试；用独立 Chrome profile 登小号，不碰主号；增量跟踪手动/低频（建议每周）。
- **理由**：实测空间列表接口对游客/高频强风控，快翻必被软限流；账号安全优先于速度，用户明确"防风控第一、接受慢"。
- **代价**：全量/深页采集慢；不能做高频自动定时。详见技能 bilibili-up-listing.md。

## ADR-008 不引入向量数据库
- **决定**：约千篇规模用 OKF 的 index 渐进式披露 + 关键词/链接导航，不做 embedding/向量库。
- **理由**：百到千篇 Markdown 靠导航+按需打开足够，向量库是过度工程，且增加单人维护成本。规模若到数万篇再评估。

## ADR-007 OCR 边界与选型
- **决定**：图文内嵌图逐张 OCR（本地 PaddleOCR 中文，先样验再批量）；视频不做全量逐帧 OCR，仅关键帧按需。
- **理由**：图文信息在图里是刚需；743 部全抽帧成本极高且多数口播已覆盖。OCR 结果标注"可能有误"。

## ADR-006 终局是"做号弹药库"，撤销量化方向
- **决定**：不做任何量化交易/行情量化系统；知识库最终服务自己 B 站号/视频号的选题与文案。
- **理由**：用户明确"量化说错了，跟量化无关"。只保留面向选题的轻量参考（基于公开播放数排序），不称量化系统。

## ADR-005 书籍走合规路径，仓库私有
- **决定**：不获取/不分发盗版全书；以正版/图书馆/公开样章为源，BookNote 以自己的话总结+少量标页引用；本地私有留存。
- **依据**：《著作权法》第 24 条个人学习研究合理使用，须署名、不影响正常使用、不损害权益；找不到的书登记待获取清单反馈用户。

## ADR-004 增量用水位、只看第 1 页、成功后移水位
- **决定**：sources.json 存 last_max_created/known ID；发现增量只拉最新一屏比对；report 与 --auto 两档；**先落地再推进水位**（at-least-once + 去重）。
- **理由**：增量发现成本应远低于全量；水位先移会在崩溃时漏数据。用 unix 整数比较规避时区问题。

## ADR-003 独立 Git 仓库且默认私有
- **决定**：在 bili-up 建独立仓 `byte886/gemology-kb`（与上层只纳管 skills 的 doubao-skills 隔离）；默认 **private**；.gitignore 排除 13G 媒体、cookie/登录态、venv、日志。（**已被 ADR-012 取代**：2026-09-14 旧私有仓删除，公有仓改名 `byte886/jewelry-knowledge`）
- **理由**：含他人视频全文转写与自有创作素材，公开有版权与"弹药外露"风险；私有可逆、公开会被镜像留痕。若日后只公开工具脚本，再拆独立公开仓。

## ADR-002 多形态"分治采集、主题融合"
- **决定**：视频/图文/书在原始层分目录独立留档（不可变），知识层用 VideoNote/ArticleNote/BookNote 区分，仅在 topics 主题页融合互证。
- **理由**：三形态可信度与信息结构不同，硬揉一篇会丢出处、难查重；主题层融合既保留差异又能一处取齐，且未来可平滑接入更多 UP。

## ADR-001 采用 OKF v0.2、本地为源
- **决定**：知识包遵循 Google Cloud OKF v0.2（内核不改），本地 Markdown 为唯一源头，成型后才考虑同步飞书；珠宝内容不进"AI 情报站"。
- **理由**：跨工具可移植、跨会话可恢复；本地可控、可校验、可 Git 版本化。
